# DX Review: agent-memory v0.1.0

## First 5 Minutes
- init/set/get/entity/search work in 5 min
- But "wow moment" (AI briefings) unreachable in 5 min — needs YAML, Claude CLI, data
- Default DB path ~/.claude/ unexpected for non-Claude users
- `set` requires 4 positional args (ENTITY TYPE KEY VALUE) — asymmetric with `get`

## API Ergonomics
- Good: MemoryStore as context manager, resolve_entity() idempotent, ScopedView abstraction
- Bad: dict returns (no TypedDict), get_slot() silent scope fallback, generate_briefing() returns Path not text
- LLMCaller union type (str | None | LLMResult) complex

## CLI Experience
- Good: Click, --db/--config globals, --json flag
- Missing: observe, relate, config show commands
- generate vs refresh naming confusing
- status command shows only entity counts (useless for debugging)

## Documentation
- README solid but no tutorial, no MCP tool docs, no scope chain explanation
- No ARCHITECTURE.md for contributors
- No examples/quickstart.py
- Error messages too minimal ("Not found" without context)

## Configuration
- YAML well-designed but no validation (typos silently ignored)
- hierarchy accepts undocumented dict format
- agents section overloaded (10+ keys per agent)

## Top 5 Actions
1. `agent-memory quickstart` with mock LLM demo
2. TypedDict returns for store methods
3. CLI: observe, relate, config show
4. Config validation + sensible defaults (./memory.db not ~/.claude/)
5. Cross-platform (fcntl) + better error propagation
